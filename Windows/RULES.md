## ⚡ 2. Новая версия при любом изменении, формат v000 и запрет версии в имени файла (Auto-Bump Version & PE Metadata)
1. **Любое изменение повышает версию:**
   - При **ЛЮБОМ** изменении, исправлении, добавлении или улучшении функций **ВСЕГДА создается следующая рабочая версия** (например, `v002` -> `v003`, `v040` -> `v041`).
2. **Формат номера версии — строго три цифры:**
   - Версия пишется строго буквой `v` и тремя цифрами: например, `v003`, `v041`, `v105`.
3. **Запрет указания номера версии в названии файла:**
   - **В названии файла версию больше НЕ пишем!**
   - Установщик называется строго: `<AppName>_Setup.exe` (или `<AppName>_Installer.exe`).
   - Исполняемый файл программы называется строго: `<AppName>.exe`.
   - Запрещено создавать файлы с суффиксами версий в названии (`<AppName>_v024.exe`, `<AppName>_Setup_v040.exe`).
4. **Обязательное заполнение свойств .exe файла (Windows PE Details & Tooltip):**
   - В свойствах `.exe` файла прописываем данные полностью через ресурсы Windows (`VERSIONINFO` / `app.rc` / `windres`):
     - `FileVersion`: точный номер версии (например, `v041` / `0.41.0.0`);
     - `ProductVersion`: точный номер версии (например, `v041` / `0.41.0.0`);
     - `CompanyName`: `VladiMIR+AI`;
     - `FileDescription`: назначение программы или установщика (например, `GIN-Voice Setup & Speech Dictation`);
     - `ProductName`: имя продукта (например, `GIN-Voice by VladiMIR+AI`);
     - `LegalCopyright`: `© 2026 VladiMIR+AI (Vladimir Bulantsev)`.
   - **Главное требование:** при наведении курсора мыши в Проводнике Windows во всплывающей подсказке и во вкладке «Подробно» свойств файла номер версии и автор должны быть видны сразу и полностью.
5. **Синхронное обновление всех файлов проекта:**
   - Номер версии синхронно обновляется:
     - В ресурсах PE (`app.rc` / `rsrc_windows_amd64.syso`);
     - В константах кода (`AppVersion = "v041"`, `AppTitle = "...[v041]"`);
     - В документации (`README.md`, `CHANGELOG.md`, `version.json`, `version.txt`);
     - В реестре Windows (`DisplayVersion`).

## 🖥️ 3. Обязательная доставка на Рабочий Стол через MEGA (D:\MEGA\DOCS\desktop)
- **Тотальное правило для абсолютно 100% всех Windows-приложений в репозитории:**
  - Во **всех проектах, скриптах и задачах для Windows**:
  - **ВСЕ новые приложения, утилиты, CMD/BAT-скрипты, PowerShell-лаунчеры и скомпилированные EXE-установщики ИИ ОБЯЗАН АВТОМАТИЧЕСКИ писать на Рабочий стол Владимира строго по пути:**
    `D:\MEGA\DOCS\desktop\` (на серверах Linux — через команду `mega-put -c "<file>" "/MEGA/DOCS/desktop/"`).
  - **После проверки Владимир сам перекладывает их в свои целевые папки.**
  - На Рабочем столе в `D:\MEGA\DOCS\desktop\` всегда содержится только актуальная копия файла установщика `<AppName>_Setup.exe` (все старые версионированные файлы удаляются).
- Сразу после сборки нового бинарника или установщика агент **НЕМЕДЛЕННО И АВТОМАТИЧЕСКИ**:
  1. Удаляет старые версионированные файлы с Рабочего стола в облаке MEGA:
     ```bash
     mega-rm -f "/MEGA/DOCS/desktop/<AppName>_Setup_v*.exe" "/MEGA/DOCS/desktop/<AppName>_v*.exe" 2>/dev/null || true
     ```
  2. Загружает актуальный установщик без версии в названии на Рабочий стол:
     ```bash
     mega-put -c "<AppName>_Setup.exe" "/MEGA/DOCS/desktop/"
     ```
     *(На локальном ПК под Windows выполняется прямое копирование в `D:\MEGA\DOCS\desktop\`)*.
  3. **Обязательно дублирует установщик в облачный каталог утилит флешки:**
     ```bash
     mega-put -c "<AppName>_Setup.exe" "/MEGA/WIN-FLASH/Util-WINDOWS/"
     ```
- **Обязательное двойное размещение:** Любой релиз установщика или утилиты (`.exe`) ВСЕГДА и БЕЗ ИСКЛЮЧЕНИЙ сохраняется одновременно по двум путям:
  1. `D:\MEGA\DOCS\desktop\<AppName>_Setup.exe` (Рабочий стол Владимира)
  2. `D:\MEGA\WIN-FLASH\Util-WINDOWS\<AppName>_Setup.exe` (Утилиты флешки WIN-FLASH)

## 📦 4. Стандарт Легковесных Онлайн-Установщиков (<AppName>_Installer.exe)
1. **Единый стандарт именования:**
   - Все компактные онлайн-установщики обязаны строго следовать формату: `<AppName>_Installer.exe` (например: `GIN-VPN_Installer.exe`, `GIN-NetScan_Installer.exe`).
   - Запрещено именование с префиксом действия типа `Install_<AppName>.exe`, чтобы файлы в проводнике Windows и каталогах облака MEGA автоматически группировались по алфавиту рядом с основным приложением.
2. **Характеристики и визуальный стиль:**
   - Нативный компактный C#/.NET исполняемый файл размером **до 50-70 КБ** (без внешних тяжелых фреймворков и библиотек, компиляция встроенным `csc.exe` .NET 4.0/4.8).
   - Обязательное внедрение фирменной иконки приложения (`/win32icon:<AppName>.ico`).
   - Автоматический запрос прав администратора (UAC elevation) при необходимости записи в `C:\Program Files`.
   - Графический интерфейс в темной стилистике с живым индикатором загрузки, процентами и отображением текущего сервера-зеркала.
3. **Динамическое определение версии и защита от устаревших зеркал (Anti-Stale):**
   - Установщик не имеет права слепо скачивать неверсионированный файл `.../<AppName>.exe` с первого доступного сервера без сверки версии.
   - Перед загрузкой установщик опрашивает `version.json` / `version.txt` (с антикэш-штампом `?t=<timestamp>`), определяя точную актуальную версию (например, `v079`) и официальный URL релиза.
   - Загрузка производится в первую очередь по версионированным ссылкам (`<AppName>_v<LATEST>.exe`).
   - После завершения скачивания временный файл проходит обязательную проверку содержимого на наличие сигнатуры целевой версии: если сторонний сервер вернул старый кэшированный бинарник, файл отбрасывается, а установщик переходит к следующему зеркалу (GitHub / CloudCore-191).
4. **Размещение в хранилище:**
   - Легковесный установщик хранится в облачном каталоге утилит `D:\MEGA\WIN-FLASH\Util-WINDOWS\...` вместо 20-мегабайтных монолитных дистрибутивов.

## 🌐 5. Синхронизация с GitHub (GitHub Project Release)
- Скомпилированный бинарник (`<AppName>_v<NEW>.exe` и `<AppName>.exe`), установщик `<AppName>_Installer.exe`, исходный код и `README.md` немедленно фиксируются коммитом и пушатся в репозитории проекта:
  - [Windows_scripts ↗](https://github.com/GinCz/Windows_scripts) — `Windows/<AppName>/`
  - [Linux_Server_Public ↗](https://github.com/GinCz/Linux_Server_Public) — `Windows/<AppName>/`
  - [Secret_Privat ↗](https://github.com/GinCz/Secret_Privat) — `Windows/<AppName>/`
- Старые бинарники удаляются из репозиториев (`git rm <old_binary>.exe`), чтобы не раздувать размер Git.
