# 📌 Обязательные Правила для Windows EXE Приложений (Strict Windows Application & Release Protocol)

> **Статус:** Абсолютный регламент для всех Windows проектов (GIN-VPN, GIN-NetScan и любых других)  
> **Владелец:** Владимир Буланцев (GinCz)  
> **Дата утверждения:** 30.10.2026

## 🔒 1. Сохранение функционала (Zero Regression Rule)
- **НИЧЕГО ИЗ СУЩЕСТВУЮЩЕЙ ФУНКЦИОНАЛЬНОСТИ УДАЛЯТЬ НЕЛЬЗЯ**, если пользователь (Владимир) конкретно и явно об этом не попросил.
- Все существующие элементы интерфейса, кнопки, логика, профили, диагностика, сетевые протоколы, горячие клавиши и контекстные меню должны строго сохраняться и оставаться полностью работоспособными при любых доработках.

---

## ⚡ 2. Новая версия при любом изменении (Auto-Bump Version)
- При **ЛЮБОМ** изменении, исправлении, добавлении или удалении функций **ВСЕГДА создается следующая рабочая версия** (например, `v023` -> `v024`, `v034` -> `v035`).
- Номер версии синхронно обновляется во всех файлах проекта:
  1. В константах кода (`AppVersion = "v024"`, `AppTitle = "...[v024]"`);
  2. В имени скомпилированного бинарника (`<AppName>_v024.exe`);
  3. В документации (`README.md`, `version.txt`);
  4. В реестре Windows и установщиках (`DisplayVersion`).

---

## 📦 3. Стандарт Легковесных Онлайн-Установщиков (<AppName>_Installer.exe)
- **Единое именование:** `<AppName>_Installer.exe` (например: `GIN-VPN_Installer.exe`).
- **Компактность и нативность:** Нативный C#/.NET (.NET 4.0/4.8, csc.exe) размером до **50-70 КБ** с фирменной иконкой.
- **Динамический опрос версии:** Перед началом скачивания установщик опрашивает `version.json` / `version.txt` (с антикэш-штампом) и определяет актуальный номер релиза.
- **Приоритет версионированных ссылок:** Загрузка идет в первую очередь по версионированным ссылкам (`<AppName>_v<LATEST>.exe`).
- **Защита от устаревших зеркал (Anti-Stale):** Скачанный временный файл проверяется на наличие сигнатуры целевой версии. Если зеркало вернуло старый бинарник, он отбрасывается, а установщик переходит к следующему зеркалу (GitHub / CloudCore-191).
- **Размещение:** Хранится в каталоге утилит MEGA (`D:\MEGA\WIN-FLASH\Util-WINDOWS\N E T\VPN\GIN-VPN_Installer.exe`). Монолитный 20-мегабайтный файл в MEGA хранить не требуется.

## 🖥️ 4. Доставка на Рабочий стол и ярлыки
- **ЗАПРЕЩЕНО копировать тяжелый бинарник на Рабочий стол (`D:\MEGA\DOCS\desktop - NO`):** Владимир обновляет программы через встроенную систему автообновления.
- На Рабочем столе размещается только чистый ярлык `GIN-VPN.lnk`.

## 🌐 5. Синхронизация с GitHub (GitHub Project Release)
- Скомпилированный бинарник (`<AppName>_v<NEW>.exe` и `<AppName>.exe`), установщик `<AppName>_Installer.exe`, исходный код, манифесты (`version.json`, `version.txt`) и `README.md` немедленно фиксируются коммитом и пушатся в репозитории проекта:
  - [Windows_scripts ↗](https://github.com/GinCz/Windows_scripts) — `Windows/<AppName>/`
  - [Secret_Privat ↗](https://github.com/GinCz/Secret_Privat) — `Windows/<AppName>/`
- Старые бинарники удаляются из репозиториев (`git rm <old_binary>.exe`), чтобы не раздувать размер Git.

## ⚡ 6. Регламент защиты от кэширования при автообновлении (Anti-Cache Protocol)
- При автообновлении всегда синхронизируются файлы:
  1. `version.json` (структурированный манифест релиза);
  2. `version.txt` (простой текстовый номер версии `vXXX`);
  3. `README.md` (публичные бейджи и ссылки).
- Любые HTTP-запросы на проверку и скачивание обновлений обязаны содержать:
  - Анти-кэш заголовки: `Cache-Control: no-cache, no-store, must-revalidate`, `Pragma: no-cache`.
  - Уникальный временной штамп в URL (`?t=<nanoseconds>`) для обхода 5-минутного TTL кэша Fastly CDN на `raw.githubusercontent.com`.
  - Математическое числовое сравнение версий `parseVersionNumber(remote) > parseVersionNumber(local)`.
