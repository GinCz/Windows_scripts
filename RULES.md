# 📌 Железное Правило для всех Windows-Скриптов: Автоматическая Выгрузка на Рабочий Стол через MEGA

> **Путь:** `RULES.md`  
> **Статус:** Обязательно к исполнению при каждом билде / обновлении любого Windows-проекта  
> **Дата утверждения:** 05.10.2026  

---

## ⚡ 1. Правило Выгрузки на Рабочий Стол (`D:\MEGA\DOCS\desktop`)

Любой скомпилированный бинарник (`GIN-NetScan_vXXX.exe`, `GIN-VPN_vXXX.exe`, установщики, иконки `.ico`) при каждом релизе **НЕМЕДЛЕННО И АВТОМАТИЧЕСКИ** загружается в облако MEGA в папку рабочего стола:

- **Целевая папка в MEGA:** `/MEGA/DOCS/desktop/`
- **Локальный путь у пользователя:** `D:\MEGA\DOCS\desktop\`
- **Аккаунт MEGA:** `gin.vladimir@gmail.com`

---

## ⚡ 2. Принцип единственной последней копии (Single Latest Version)

На рабочем столе пользователя **НЕ ДОЛЖНО БЫТЬ СТАРЫХ ВЕРСИЙ, ДУБЛИКАТОВ ИЛИ ФАЙЛОВ БЕЗ ВЕРСИИ В ИМЕНИ**.  
На Рабочем столе в `/MEGA/DOCS/desktop/` находится **ТОЛЬКО ОДИН файл — единственный установщик с актуальной версией в названии** (например, `GIN-Voice_Setup_v018.exe`, `GIN-VPN_v021.exe`).  
Перед выгрузкой новой версии обязательно удаляются все предыдущие версии и любые неверсионированные бинарники (`GIN-Voice.exe` и т.д.):

### Команды деплоя:
```bash
# 1. Удаление старых версий и дубликатов
mega-rm "/MEGA/DOCS/desktop/<old_binary>.exe" 2>/dev/null || true
mega-rm "/MEGA/DOCS/desktop/<binary_without_version>.exe" 2>/dev/null || true

# 2. Выгрузка ЕДИНСТВЕННОЙ новой версии
mega-put -c "<path_to_new_binary_with_version.exe>" "/MEGA/DOCS/desktop/"
```

Любая сессия, где создается или модифицируется Windows-приложение, считается завершенной **ТОЛЬКО** после успешной выгрузки файла в `/MEGA/DOCS/desktop/` и проверки наличия ровно одной актуальной копии.

## ⚡ 3. Железное Правило Версионирования (Любое малейшее изменение повышает версию)

1. **Любое малейшее изменение повышает версию:**
   - Каждое, даже самое минимальное изменение кода, фикс бага, добавление фичи, рефакторинг или изменение настроек/интерфейса **ОБЯЗАТЕЛЬНО повышает номер версии** (например, `v017` -> `v018`).
2. **Синхронное обновление всех файлов проекта:**
   - Номер версии синхронно обновляется во всех сопутствующих файлах (`main.go`, `version.json`, `version.txt`, `README.md`, `HELP.md`, `setup_guide.html`).
3. **Единственный релизный файл:**
   - На рабочем столе и в репозитории остается только последний актуальный релиз.

## ⚡ 4. Железный Регламент Автообновления и GitHub Синхронизации (Zero-Desync Pipeline)

1. **Архитектура встроенного обновления:**
   - Пункт контекстного меню в трее **«Проверить обновление»** и встроенные апдейтеры приложений опрашивают GitHub:  
     `https://raw.githubusercontent.com/GinCz/Windows_scripts/main/Windows/<Project>/version.json`
   - И скачивают исполняемый файл:  
     `https://raw.githubusercontent.com/GinCz/Windows_scripts/main/Windows/<Project>/<App>.exe`
2. **Запрет рассинхрона (MEGA без GitHub):**
   - Категорически запрещено выкладывать новый установщик в MEGA (`/MEGA/DOCS/desktop/`) без синхронного коммита и пуша на GitHub (`git push origin main`).
   - Если установщик на Рабочем столе уже обновлен, а на GitHub осталась старая версия `version.json` — запущенная программа при проверке обновлений ложно сообщает: *«У вас последняя версия»* и отказывается обновляться.
3. **Строгая последовательность релиза:**
   1. Компиляция и сборка бинарников (`.exe`, `Setup_vXXX.exe`).
   2. Синхронное обновление `version.json`, `version.txt` и документации.
   3. `git add`, `git commit` и `git push origin main` на GitHub.
   4. Проверка ответа: `curl -s https://raw.githubusercontent.com/GinCz/Windows_scripts/main/.../version.json` == `vXXX`.
   5. Очистка старых версий и загрузка инсталлятора в MEGA `/MEGA/DOCS/desktop/`.

## ⚡ 5. Железное Правило Кликабельных Ссылок и Репозиториев (Clickable Links & Repos Mandate)
1. **Строго кликабельные markdown-ссылки со стрелочкой `↗`:**
   - Все ссылки, передаваемые пользователю (Владимиру) в сообщениях, ОБЯЗАНЫ быть кликабельными ссылками на GitHub со стрелочкой `↗` на конце (например: `[Windows_scripts ↗](https://github.com/GinCz/Windows_scripts)`).
   - Категорически запрещено отправлять локальные файловые ссылки (`file:///...`) или некликабельный плоский текст путей.
2. **Обязательная кликабельная ссылка на репозиторий при любых коммитах:**
   - При внесении любых изменений (commit, push) в проект `Windows_scripts` или связанные репозитории, агент **ОБЯЗАН в тексте своего ответа предоставить прямую кликабельную ссылку на конкретно этот репозиторий на GitHub**.

## 🏷️ ПРАВИЛО НАИМЕНОВАНИЯ ЧАТОВ И ТЕМ (Chat Title Naming Convention)
1. **Строгий стандарт названия темы/сессии:**
   - При создании нового диалога или получении любого вопроса/задачи в рамках этого проекта, тема чата (Chat / Topic / Session Title) **ОБЯЗАТЕЛЬНО** должна именоваться строго в формате:
     `Windows_scripts - <Краткое описание задачи>`
   - *Примеры:*
     - `Windows_scripts - Описание задачи`
     - `Windows_scripts - Исправление ошибки плеера`
     - `Windows_scripts - Добавление новой функции`
2. **Исключение ручного переименования:**
   - ИИ-агент обязан автоматически формировать тему чата строго с префиксом `Windows_scripts - `, чтобы Владимиру никогда не требовалось переименовывать темы вручную.

## ⚡ 3. Железное правило обязательного повышения версии (Strict Version Increment Mandate — Strict in Every Project!)

- **Каждое изменение, каждая поправка — новая версия!** При любых доработках, изменениях кода, скриптов, интерфейса, конфигов или добавлении модулей в ЛЮБОМ проекте (Windows-скрипты, Android APK, боты, веб-приложения) **ИИ-агент ОБЯЗАН немедленно повышать версию проекта** (`v031` ➔ `v032`, `v001` ➔ `v002`, `1.0.0` ➔ `1.0.1`).
- **Категорический запрет на правку релизов «на месте»:** Строго запрещено молча вносить изменения в уже выпущенный файл без инкремента версии. Любая модификация обязана создавать новый версионированный артефакт.
- **Сквозная синхронизация:** Новая версия синхронно обновляется в имени файла/установщика, манифестах (`version.json`, `package.json`, `build.gradle.kts`), заголовках GUI и консольных логах, документации (`CHANGELOG.md`, `README.md`, `WORKLOG.md`) и коммитах Git.
- **Правило ротации 2 последних версий:** На рабочих носителях (`V:\WIN-FLASH\`, `D:\MEGA\WIN-FLASH\`, Samba `/storage/user/`) хранятся строго 2 последние версии (актуальная и предыдущая). Более старые версии автоматически удаляются.
